# Architecture decision · 2026-10-09

## Language and desktop stack

C# is the appropriate choice: TKR.WorldServer and TKR.Shared already implement the source-authoritative behavior and gameplay logic in C#/.NET 8. The existing BossPatternSim test host provides a no-network bootstrap for the real engine. Rust would require an interprocess C# host without a demonstrated advantage for this first workflow.

The first desktop implementation uses WPF on Windows and .NET 10, both available in this workspace. WPF provides native desktop rendering, keyboard input, split panes and a straightforward custom viewport. Core document code stays separate and portable. Desktop/credential storage are Windows specific. Arbitrary docking and portable rendering are later milestones.

The engine assemblies remain .NET 8 targets. The current desktop executes their IL on .NET 10. One independent original .NET 8 capture is compared with Studio; that does not certify all cross-runtime numerical behavior. A .NET 8 runtime child host is the recommended follow-up if broader differential evidence finds runtime-version differences.

## Shared document and fidelity boundary

Arena presets are versioned project data alongside the source document. Ground/static object IDs resolve through the same native XML dictionaries as the world. The adapter exports its bounded 128×128 prototype tiles with the game's WorldMapExporter and reloads them with native World.FromWorldMap. The offline player is detached from the old collision index before insertion into the new index. Primary and additional enemy positions validate against native arena geometry and passability before creation. A separate arena history commits whole brush strokes; source undo retains its existing behavior outside arena editing. Changes stop/cancel affected runs, previews, recordings and AI proposals. Sparse immutable scene snapshots track native tile changes and cross the compiled-host protocol as deltas; replay witnesses hash scene content with presentation revisions removed. This supports the native prototype world, while arbitrary world bootstraps, multiple actual players and full player/client mechanisms remain separate fidelity gates.

Native map authoring uses a separate immutable full-dimension cell image and map history. A bounded reader accepts the game’s version 0/1/2 dictionary/zlib format; actual WorldMapExporter writes native version 2 and atomic file saves. Dimensions, original ground/object IDs, dynamic records, configuration and byte metadata survive authoring even where Wmap derives connected-object data or removes dynamic tile objects during load. A detached actual World/Wmap provides passability without player/entity startup or native RNG reseeding. Inspection is asynchronous and requested in Inspect mode; visible-tile drawing and a cached overview avoid rendering every tile at each zoom level. Limits bound grid, file, string and native signed-short dictionary sizes.

Prototype transfer retains every source cell and rejects unsupported dimensions/world entities before changing the encounter. Primary and extra enemy configuration uses actual Wmap.CreateEntities, with size/name introduced in protocol v6 and included in replay state. Configuration-free actors keep their existing native spawn path. Map drafts recover independently of source projects; replacing or closing an edited map waits for native recovery, and final window disposal is queued after the canceled Closing event returns. Map save protects the supplied game checkouts. Full original-world bootstrap, actual players and broader world prerequisites remain separate gates.

The adapter established that behaviors are **C# DSL expressions**, not XML. The complete source text and Roslyn syntax tree form the document. Graphs, inspector, source editor, AI patches, runtime binding and export all reference that document. Editor IDs/locks/layout metadata live in `.rbs`, never in unsupported server attributes.

Import finds literal-ID `.Init` calls with native State constructors and, with the original source file context, State-returning factories and shared field/property values. It retains everything else losslessly: comments, loot, custom expressions, helper methods and unrelated entity definitions. Calls expose their arguments and remain Factory/Reference nodes. A separate `Definitions` collection catalogs actual current-file native child/collection declarations, with exact body spans, semantic keys, independent IDs and known native callers. Helper returns, fields, getters and local values navigate to their original editable bodies; conditional/switch returns retain separate branches. Discovery never executes authored code or substitutes runtime inputs. Unused declarations retain IDs and locks when calls disappear. Known external references and incomplete control/input contexts block complete phase reconciliation. Visual edits replace source spans instead of regenerating the file. Multi-file dependencies and generated algorithms remain source boundaries.

NativeRegistrations resolves only the original BehaviorDb.ctor.InitMany method symbol. Constant/named endpoints map to the native inclusive numeric type range and canonical ObjectTypeToId values. Inline lambda bodies project one exact source State into independent per-entity editor identities. Candidate projections do not prove global registration ownership: local chain order reconciles explicit definitions, while compiled initialization runs the real factory and preserves native skip/precedence semantics across fields/files. Numeric XML gaps retain an explicit native-failure boundary; delegate/block factories remain opaque rather than being executed for discovery. Range facts are cached per semantic source context and carried into PreparedBehaviorSchema (introduced in protocol v6). Library authoring includes actual pet templates; known PetFollow inputs require an actual Pet and owner before prototype playback.

IDs are persisted with structural paths and expression signatures. Parameter edits and append operations retain IDs. Explicit structural operations carry an identity layout into the candidate document: even identical actions keep their own IDs when reordered or deleted, while duplicated branches allocate fresh IDs. Shared range edits rewrite physical source slots once and project structural orders into every variant; equivalent region locks and known phase references include those aliases. Identical parameter proposals deduplicate, conflicting values reject atomically. Unique source expressions retain IDs when moved through source editing; arbitrary source restructuring of identical expressions remains an identity reconciliation limitation.

Structural edits replace only syntax argument lists or literal expressions. Phase rename rewrites known literal targetState references within the same entity; copied nested phases receive unique names and internal targets follow those copies. Deletion removes incoming transitions targeting deleted named phases as part of the same commit. Ancestor/descendant locks and locks on rewritten transitions prevent the entire edit. Ambiguous dynamic/opaque phase references and unresolved child-slot schemas are rejected before mutation. Known native arrays/wrappers use the same structural operations. The inspector and parameter-proposal rename path call these same document operations, and every edit discards the current runtime session before the next Play.

Revision checks, locks and undo are in Studio.Core. A patch validates a candidate before committing. Failed edits preserve the last valid document. Full source replacement requires unlocked regions. Undo history is session-local. Source syntax and reference checks are immediate; compilation against all original server files is the export gate.

Bulk selection normalizes ancestor/descendant selections, retains source order, and rewrites affected phase argument lists in one validated commit. Cross-parent moves keep IDs; clipboard paste allocates independent nodes and reconciles literal internal phase references. Nested ancestor edits use Roslyn's rewritten child nodes so a removed child cannot be accidentally reintroduced. Separator comments travel with moved/grouped arguments. Grouping authors a real nested State; ungrouping promotes its contents only after incoming phase references are rerouted. Clipboard v1 contains selected constructor expressions, never the entire imported source. Desktop drag payloads carry revision/entity IDs; stale drops are refused. Collapse is view metadata in the readable v1 project, and older projects default to an empty collapse list.

Studio.Core's BehaviorAnalysis describes direct phase transitions in their native filtered source order and computes conservative reachability through first-child descent and transitions inherited from active ancestors. It reports unreachable phases only when all nodes are recognized and destinations are literal/unambiguous. Opaque/custom content, dynamic destinations and duplicate phase names suppress those reports. Predicate conflicts cover broader preceding HP/player-distance checks and unconditional zero-time timers; nonzero stateful timers are not treated as stateless predicates. Self transitions are advisories: the native common ancestor can suppress entry/exit callbacks, so a self edge does not imply a full restart. These diagnostics are kept separate from RapleAdapter's blocking validation. The graph exposes condition hit targets and draws only the selected transition route; the collapsed Phase review navigates by the document's existing node IDs.

## Runtime hosting

Studio.Raple references the actual private server project and links its unchanged `tests/BossPatternSim/SimEngine.cs`. This bootstrap bypasses account/network startup, creates a real BossLabWorld, initializes BehaviorDb and captures EnemyShoot packets at the existing player broadcast boundary.

A restricted interpreter binds literal constructor expressions to actual runtime classes. That quick-preview path never executes arbitrary source expressions. `State.Resolve`/`ResolveChildren` run from the supplied assembly. Edited definitions are installed only in the local host. A fresh BehaviorDb per run prevents mutable Shoot rotation fields from leaking across runs.

When imported State arguments require source context or custom classes, the desktop compiles the complete original WorldServer source set with the edited file substituted and starts Studio.RuntimeHost with that DLL in a private bundle. The emitter retains native assembly identity and declared embedded resources, plus portable PDBs. It never overwrites the server checkout or desktop dependencies. Bundle reuse validates every expected file; changed source/reference/host/resource/CLR inputs change the build identity, and corrupted bundles are replaced with a fresh directory. Traces and export sidecars retain those fingerprints. Client asset provenance and broader certification invalidation remain pending.

SourceBehaviorSchema uses a reusable, un-emitted compilation of the complete original source set and .NET 8/server references, substituting the edited tree. Source/reference metadata changes invalidate its baseline. Binding is scoped to the exact expression position; constructors, overloads, native types, aliases, variables and defaults come from actual C# symbols. Aliases that change the selected constructor require compiled execution, so a familiar short name cannot substitute a different game primitive. Dynamic State names remain scalar source values and suppress definitive name-based reachability checks. Semantic errors in the edited file reject edits atomically. No source helper or property getter executes during authoring. Native startup reuses the compiler that emitted the assembly to prepare presentation bindings for native callers and source definitions, then sends those facts, definition metadata and native registration projections with protocol version 7. The worker consumes PreparedBehaviorSchema rather than rebuilding a semantic compilation inside its startup time/memory limits. Definition views change authoring focus only; native execution still uses the original emitted loader and factory calls.

The child uses the same EncounterSession/bootstrap with the compiled production BehaviorDb definition rather than interpreter binding. It keeps initialization, ThreadStatic RNG and all commands on one thread. Versioned JSON requests/responses use stdout; native console output drains separately through a bounded stderr log. Sequence/size checks, startup/command deadlines and sampled working-set limits stop failed execution; the process tree is killed and cannot resume partial state. A background parent-lifetime watcher exits even if a native callback never returns. These mechanisms contain ordinary failures; compiled source has the user's OS access and is not sandboxed. Compilation/preparation budgets and OS resource enforcement are still pending.

IEncounterSession shares presentation data between preview paths. Compiled responses carry immutable entity/motion/projectile snapshots and append-only deltas; the client publishes immutable event/shot/input lists for asynchronous UI readers. WPF awaits preparation and ticks, serializes active advances, cancels stale starts on edits/entity changes, and disposes processes on Stop/replacement/close. Native phase navigation retains unique visible identities; factory/inherited/grouped attack attribution stays unknown until real source instrumentation exists. The local application simulation tool uses the same compiled path when needed. Export checks both compilation and original behavior-database loading before the save dialog; successful loading does not certify tick/player/client fidelity.

IBehaviorSchema supplies per-expression parameter slots and actual child argument types to the lossless document. NativeConstructorSchema builds an un-emitted Roslyn semantic compilation of public signature mirrors, reflecting constructors, inheritance, optional defaults, params arrays, helper types, internal enums and conversion operators. Constructor attributes identify the exact native metadata token. C# chooses the overload and conversions; the interpreter evaluates supported constants/arrays/constructors and invokes that native constructor. No mirror body or arbitrary user code executes. Unknown source identifiers/factories require context and cannot be guessed during local simulation. Literal array-held behavior trees have typed structural views and can execute when supported; factory-generated arrays still need source-context resolution. Missing-target authoring diagnostics are conservative when opaque arguments can contain targets; native Resolve still validates the actual tree.

RapleAdapter derives lifecycle stage/provenance from actual overriding method declarations, omitting empty callbacks. The phase inspector lists direct and ancestor actions and opens their original node for editing. These are fixed native callbacks, not independently assignable editor stages. ConditionEffectBehavior executes native entry application and exit removal, including its permanent flag; common-parent actions remain active across child transitions.

ArgumentGroup is a view/model boundary for a native child parameter, never a runtime behavior. It can represent an actual array initializer or a scalar/expanded/omitted slot backed by its containing call. Multiple child slots have separate named groups. ChildArgument supplies native element type, params/scalar cardinality and runtime minimums; optional scalar slots permit zero children, while required scalar slots require one. Structural operations resolve the actual slot and rewrite either call arguments or an array initializer, retaining named arguments and array element restrictions. An inferred array made empty becomes an explicitly typed empty array so its actual type is retained. Source rewrites update nested children before their ancestors; identity layouts include the argument-list nodes. Legacy opaque-array and flat multi-slot child IDs migrate into their new boundaries, preserving locks. Only StateChildren flattens the State's array boundary for phase inheritance, transition priority, graph entry and direct attack provenance. Generic wrapper contents do not become phase-owned actions.

Call-backed groups share the owner's physical source span but use slot-qualified identity signatures. Rewrites aggregate changes to all slots sharing that syntax node, so a move can remove and insert children atomically. Removing/inserting optional positional arguments normalizes remaining formal names and expanded params into genuinely typed arrays where necessary; existing named syntax and comments survive. The adapter supplies actual array element spelling. Null/omitted optional arrays remain unassigned until an edit materializes them; current-file shared arrays navigate to their definition bodies, while unresolved generated inputs require Source. Scalar replacement checks the previous child's locks and hidden phase-reference constraints. Runtime presentation bindings deduplicate physical span/expression keys before crossing the process boundary.

Source-aware insertion and clipboard parsing replace the destination encounter root temporarily with the adapter's native State wrapper inside the complete edited source file. This retains namespace, helper, member and local scope without executing source code. The fragment must resolve to native children before structural validation; the complete final candidate is compiler-checked before commit. Factory/reference nodes use the same typed slots and identity layout as constructors. Shared references are copied as expressions, preserving actual C# object sharing. Named-phase copies and rename/delete rewrites remain blocked when helpers could hide affected references.

Array-targeted CollectionExpressionSyntax is a native child-list boundary. Expression elements become ordinary source nodes; spread elements retain the complete spread syntax as separately identified inputs. Rewrites preserve brackets, separators, internal spread comments and source expressions. Structural spread operations require a collection destination and use target-typed collection fragments in the complete source context. The original compiler gates element conversions and binding without executing helpers/getters. Literal collections can instantiate native arrays in the restricted executor; spreads always use compiled preview. Spread contents are never invented in the visual tree, and phase-reference/reachability analysis remains conservative. Source-bound generic enumerable targets also use typed lists, including IEnumerable/IReadOnlyList/List and actual CollectionBuilder types. ChildArgument retains its declared CollectionType separately from IsArray; IsCollection controls list cardinality without changing scalar semantics. Source binding derives the native element type from the real IEnumerable contract, while the complete compiler gates construction and spread conversion. Omitted/null inputs use target-typed brackets. The editor does not execute enumerators/builders or invent controller callback order; compiled checks exercise real helper/builder/controller dispatch. Single-input collection initializers on explicit/implicit object creation are child-list boundaries. Rewrites change only initializer elements, retaining constructor arguments and braces. Empty object-initializer syntax is accepted as an empty collection only in an actual non-expanded collection slot; scalar/expanded behavior initializers are not mistaken for child lists. Concrete collection element types constrain insertion even when the formal input is a wider enumerable. Multi-argument Add and member/index initializers remain source regions. Native behavior/State object initializers add opaque source nodes, force compiled execution and block unsafe hidden-reference/child assumptions. Authoring never executes collection constructors, enumerators or Add methods. Compiled traces execute custom reversed Add order and native State collection-member initialization. Current-file declarations have separate definition views; generated algorithms and external dependencies remain source regions.

Timed and OnDeathBehavior are native runtime primitives, not editor approximations. Timed calls child entry methods, then subtracts tick duration inside its per-child ongoing loop. OnDeathBehavior forwards death to its child's entry method. EffectiveCallbacks filters/maps wrapped-child stage displays accordingly; exit/death are not forwarded by Timed/Prioritize. Other wrappers remain incomplete rather than receiving invented dispatch semantics.

The real enemy executor runs in 100 ms steps; sampled client/player interaction runs in 5 ms steps. CompositionTarget.Rendering advances the accumulated whole 5 ms samples on each display frame; enemy ticks remain independently aligned to 100 ms boundaries. This removes the former 100 ms player movement bursts without interpolation changing collision positions. Playback speed changes accumulated time, never gameplay step sizes. Each simulation remains single-thread confined because Behavior/Transition RNG and BehaviorDb.InitDb are thread-local/global initialization assumptions; compiled previews keep this confinement inside their separate process.

Viewport character bounds follow Camera.as/TextureRedrawer's source scale and bottom padding. Projectile points and target overlays share the client's z=0.5 projection, with mouse aim inverted through that same plane. ClientSprites follows AnimatedChar's direction rows, two-frame walk/attack sequences, seven-column symmetric walk fallback and centered extended weapon composites. Player animation uses actual sampled movement speed and the last weapon volley's attack period.

The opt-in Shoot editor reads only compiler-known numeric constants from a genuine native Shoot binding. No helper, getter or native constructor executes during geometry inspection. Its centered fan follows native spacing, fixed/player-targeted/fallback aim, offset and instance rotation in degrees. Authoring uses the static enemy/player prototype positions and the same hit-plane inverse projection as gameplay. Radius is target-search distance in tiles; origin is the native host position and direction rays are schematic, not projectile range/trajectory. Dragging changes only the transient overlay; release uses the shared typed parameter patch with the captured node/revision and one undo. Escape, capture loss, selection changes and locks cancel transient edits. Play exits the editor and creates fresh native behavior instances.

Each enemy tick captures immutable EntityMotion endpoints around the actual engine tick. The viewport samples that segment using simulation time plus the unconsumed frame fraction, matching GameObject.onTickPos/update's linear movement toward the new tick position. Sprite, shadow, health bar, depth ordering and displayed hitbox share this pose. Walking uses the client's velocity-based period rounded to the next 400 ms multiple and full movement direction. Newly spawned entities use their spawn position; catch-up keeps the latest segment, sampling clamps at endpoints, and pause freezes simulation time. These endpoints are presentation data: runtime positions, collision, targeting, projectile origins, timers and traces remain authoritative and unchanged. Full client collision interpolation/Goto packet semantics remain outside this implementation.

The test actor has an independent real ConditionEffectManager, native Inventory with one XML weapon, and original StatsManager/BaseStatManager/BoostStatManager instances backed by offline stat arrays rather than a database character. GameWeapon reuses ClientRandom, OnShootProcTracker and ActivateBoost; projectile hits call Player.EnemyHit and native enemy deaths. ClientCollision shares XML target geometry with the viewport; ClientTrajectory supplies the client's parametric parity while reusing other supported server motion formulas. Client interpolation, networking, special hit activations, grenades, abilities and the complete player lifecycle remain absent. This boundary is visible in the UI and every trace.

AI simulations stop an active interactive run, bind a candidate document and run a bounded stationary scenario. This avoids introducing a second run into the shared RNG context. Entity/projectile/time limits are checked at simulation boundaries. Replay inputs include their sample duration (default 100 ms for older records) so display-frame input boundaries can be reproduced; UI seeking/snapshots/checkpoints are pending.

## Movement authoring

Movement authoring binds genuine native Follow/Orbit/StayCloseToSpawn constructors through the same scoped compiler. Numeric/string/bool constants are inspected without executing source; unknown speed values do not prevent editing independently known geometric boundaries. Follow uses a host-centered acquisition radius and a target-centered stop radius plus its native one-tile resting hysteresis. Orbit preserves signed radius variance, nullable seeded direction and actual entity target IDs. StayCloseToSpawn uses an integer range around the position captured by its real OnStateEntry callback. The viewport shows prototype boundaries, not a simulated trajectory; readable sprite markers have a minimum screen size and are not collision bounds. Gameplay rendering keeps its original source scale. Gesture completion and direction changes use one typed revision/lock-checked patch. Editor modes are exclusive, retain the prior gameplay camera and stop actor input; Play creates fresh native instances. Native checks preserve Follow/Home's BehaviourTickTime and Orbit's distinct DeltaTime factor.

## Projectile resources

The enemy projectile picker reads the real native XmlData ObjectDesc.Projectiles dictionary without renumbering indices. It retains raw damage/lifetime/speed and texture references; displayed base speed follows the client's Speed/10 tiles-per-second conversion. It displays source motion/effects and the existing local playback limitation. Owner inference is limited to genuine native State/Timed/Prioritize/OnDeathBehavior dispatch and typed list boundaries; source factories/custom controllers keep their owner boundary. Projectile-index constants resolve independently of other unknown Shoot arguments. Browsing never writes source or executes getters. Use projectile validates the owner/index again, then applies one typed revision/lock-checked document patch and preserves save/undo identities.

## AI

Studio.AI owns its own persistent host ID and account registrations; tokens are Windows DPAPI protected. Existing registrations retain their issued OAuth client ID. Refresh and sign-out serialize using an exclusive per-registration file lock and reread the latest stored rotating credentials.

Codex is a local child process over stdio. The app supplies ACCESS_TOKEN, uses the official ChatGPT-plan Responses provider, and owns renewal. When the token changes, the process is replaced and its saved thread resumed. No developer API key or credentials from another application are used.

Tools are namespaced application functions, matching the generated Codex 0.160.1 experimental protocol schema. Tools inspect selected context, search constructors, propose parameter patches, run bounded current/proposed simulations and inspect traces. Mutations remain proposals until user Apply. Core validation and atomic undo apply to manual and AI operations equally.

Live authentication/inference is unverified. The offline protocol peer is explicitly test-only. No mocked response is displayed as live AI. The UI permits editing, save, export and Play independently of AI availability.
