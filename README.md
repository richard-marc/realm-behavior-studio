# Realm Behavior Studio

A working Windows desktop encounter editor for the supplied Raple Realms source. Version 0.1 is an incremental implementation, not the full product described in the roadmap.

**This server uses C# behavior definitions, not XML behaviors.** XML defines entities, projectiles, tiles and equipment. Studio imports C# `.Init(...)` definitions, preserves the complete source, edits the same document that Play consumes, and checks exports with the original compiler and native loader before writing them.

## Run

Install the .NET 10 SDK on Windows, then double-click **Start Studio.cmd**. The supplied workspace already has the SDK. This builds the app and opens its workspace. No Redis, game login, running server or AIR client is needed for Studio's current local test host.

The refreshed workspace uses a graphite theme, matching dark dropdowns, separate Encounter/Behavior/Source/Details views, and a full-width console. Drag the divider above Console to resize it; the two rightmost console buttons expand or collapse it. Panel sizes are saved with projects and remembered between launches. Parameter explanations are available on hover, with optional settings collapsed by default.

Select an action and **Add to state** to choose a real game constructor, fill its fields and inspect the source preview. Overloads, named arguments, arrays and optional defaults follow C# rules. Repeated arguments such as Taunt messages have separate editable fields. A phase's collapsed **Lifecycle** view shows its native callbacks and inherited parent actions; select a row to edit the original action. Imported original server files also expose helper arguments and compiler-resolved source constants. Factory and shared State roots appear in the library and graph. **Edit [definition]** opens a helper return, field, property getter or typed collection from the current source document. The banner identifies its known callers; **Return to encounter** restores the call view. Play uses the actual compiled helper and its original arguments.

Recorded attack and effect events now carry the native callback that emitted their packet. Timeline selection opens that action or controller, even when two actions use the same projectile or the enemy changes phase during the tick. Packet ownership and controller identity remain separate. Untracked helper constructions and timer registrations retain visible source boundaries. Compiled callback recording links delayed packets to their actual world-timer invocation and separately to the action that scheduled it.

Select a phase, action or custom controller and expand **Observed callbacks** to inspect actual native dispatch order. **Play with callback recording** starts a fresh compiled run; nested rows show the controller/child call relationship. Selecting a row opens its recorded construction site while retaining playback. Callback records stay out of the console, refresh twice per second while playing, and refresh immediately when paused. Complete transcripts are included in traces and checked during replay. Timer rows show delay, invocation number, actual dispatch result, handler, scheduling call/actor and entity owner. Selecting a timer row opens the accepted scheduling action; it does not label the timer invocation as that action's tick.

Compiled previews load the edited complete server assembly in a separate process, retaining its embedded resources. The workspace stays available while preparing; Stop, switching entities or editing cancels the start. Native startup/tick failures stop that process. Source/build/resource/runtime fingerprints accompany traces and export verification. This expands executable source coverage; it does not certify all custom game-context, player or client mechanics. Source code executes with the current user's access: process separation is not a security sandbox.

Native OrderedBehavior has a collapsed **Ordered dispatch** panel. Select a child to edit its constructor fields; Organize → ↑ / ↓ changes its priority. NewFollow, NewCharge, NewWander and NewStayAbove use the game's ordered callbacks. The panel explains false fallthrough, inherited no-op blockers and state retained across phase exit. Direct phase placement is flagged; NewStayAbove needs RealmWorld elevation and does not move in this Boss Lab prototype.

Native collection constructors can also receive their first entry without pre-existing initializer braces. Adding retains explicit or target-typed constructor syntax, arguments and comments. The inspector counts authored entries; content produced by the original constructor still runs during Play.

Indexed initializers such as `[key] = action` now expose their actual keys and native setter value. Edit, create, reorder, duplicate or copy complete entries without changing their syntax. Multi-key and named indices, native value arrays and native-value dictionaries follow the original property setter and enumeration order.

Collection entries also support Add extension methods visible in the current source. The form edits the actual key/native child inputs and follows C# instance-method precedence, imports, params and optional defaults. Generic extension contracts are available when the receiver resolves their native child type.

Select an explicit native collection, including an empty one, and expand **New entry** to choose an actual Add overload. The form prepares scalar values and required/optional native children together. Creation checks the selected overload, preserves comments and identities, and supports one-step Undo/Redo. Inherited constructed-generic contracts and params arrays are supported; generated collections and entry-owned phases retain their source ownership gates.

Native child arrays appear as quieter rows such as **children · 2**. Select their contents to edit, reorder, duplicate, copy/paste or drag compatible actions into another typed list. The editor preserves the array's actual type and rejects incompatible children. Select a list or wrapper when adding a child. Prioritize starts with an editable native Wander child. Timed and OnDeathBehavior use the game's real callback rules; the lifecycle inspector shows the child's actual dispatch stage.

Helpers and source constructors with several native child parameters show a separate named slot for each scalar, array or expanded params list. Select the exact slot before using an action: occupied scalar slots offer **Replace child**, and optional empty slots can be filled again. Optional arrays remain visibly unassigned until a child creates their actual typed array. Cross-slot moves preserve the other arguments' C# binding, identities and undo. Shared collections with a declaration in this document offer **Edit [definition]**; unresolved or externally defined inputs retain **Open Source**.

Array and source-bound enumerable/read-only/concrete C# collection expressions such as `[new Wander(.2), ..sharedBehaviors]` expose the same typed child lists. Explicit children and spread inputs support reorder, duplicate, copy/paste, moves, deletion and undo; spread inputs move between collection lists while preserving their source expressions. Their values expand in compiled Play, preserving C# evaluation and sharing. Empty lists retain `[]`, and literal collections can use ordinary native playback. Source helpers and custom controllers can expose IEnumerable, IReadOnlyList, List and actual CollectionBuilder inputs. Filling an omitted or null input creates a target-typed collection; incompatible children or unconstructible targets reject atomically. The hierarchy shows source input order, and compiled Play runs the actual helper/controller dispatch. Ordinary collection initializers and target-typed new(...) initializers also support child-list editing while retaining their constructor arguments, braces and comments, including empty lists. Compiler-bound keyed Add entries expose scalar values and one or multiple required, optional or collection-valued native behavior inputs. Select a named child slot to replace it, or use New entry to create all inputs together in one undoable edit. Native State behavior/transition member lists also support typed editing. Leave optional New entry fields blank to use the game defaults; removing an optional child restores its default while preserving later inputs. Select an entry-owned list to reorder, add, remove or move its typed elements. New entry accepts a complete list expression; blank required lists create empty native collections. Expanded params Add inputs also support typed lists; empty refill and new-entry creation materialize explicit native arrays. Referenced/generated lists and unsupported object/index initializers retain visible source regions and use compiled playback; Open Source selects the exact expression. Current-file helper/getter bodies open through their definition controls; other control flow remains in Source.

Terrain waves use original game ground XML and tile sprites. Choose source/destination grounds, radii, delay and duration; the timing preview follows the native moving front. Enable the test-arena option to override the game's Boss Lab exclusion. Restoration follows actual exit/death callbacks and can overwrite later changes to affected cells. Ground hazards retain the prototype's existing player-mechanics limits.

Sky strikes expose native target, grid, chain and halo layouts with real fuse marks. Choose area damage or actual owner XML core/shrapnel projectiles. The preview shows opening geometry; Play runs the original placement and impact code. Native area damage updates the HP display using original player defense and immunity formulas. Test-player death is reported locally; database-backed character death and reconnect remain outside the prototype.

Trail ledgers stamp observed player positions; movement recounts resample recent paths with native spacing and fuse timing. Choose actual moving XML shards and inspect the collapsed history/bounds preview. Play uses the original glyph engine, including merge rules, caps, aimed interest, cleanup and shared-instance state. The native boundary-animation bug is retained; its penalty timing still applies.

Helper calls and shared references in typed child slots support duplicate, reorder, move, copy/paste, delete and undo. Copies of shared references retain the same source value; helper copies retain their original arguments. Paste binds in the destination's complete source scope and rejects unavailable helpers or incompatible native types. Definition edits change the original declaration once for its callers; IDs, locks, undo and the focused view survive project reopen. Locked calls protect transitive shared contents. Removing the last call retains declared body identities and locks. Phase rename reconciles fully discovered literal references across known callers. Conditional returns expose separate source branches; other statements and unresolved child inputs keep an explicit reconciliation boundary. Discovery does not execute helpers/getters or substitute runtime arguments. Generated algorithms remain in Source; shared helpers also open their original definitions across project files. Wrong helper argument types and compiler errors preserve the last valid document. Source binding requires the original server file path saved in the project.

Entity thumbnails, enemies, the Wizard test character and projectiles use the supplied client's actual PNG sheets. Studio reads the client texture registrations and resolves the source XML's texture indices, including hex indices and animated character cells. Pixel art stays crisp while zooming. Sprites are loaded from the private client checkout, not bundled into the public application. Unsupported/missing texture registrations show a placeholder; alternate skins, procedural rendering and full client animation parity remain incomplete.

```powershell
./start-studio.ps1
# Another checkout:
./start-studio.ps1 -ServerRoot C:/path/to/raple-realms-7-server -ClientRoot C:/path/to/raple-realms-7-client
```

To build directly:

```powershell
dotnet build src/Studio.Desktop -c Release
dotnet run --project src/Studio.Desktop -- --server ../raple-realms-7-server
```

Build-time `-p:ServerRoot=...` controls references to private source. Run-time `--server ...` selects its resources and source catalog. They must refer to the same revision. Rebuild when changing private server source; restart Studio when changing resources. Private dependencies are intentionally outside this application directory.

The launcher builds into a directory identified by the application/server source version, allowing a refreshed build while an older window remains open. Save work in the older window before switching to the new one. Direct launch also accepts `--client <client folder>`; the sibling client is the default.

## What Play currently means

Keyed Add entries show their actual key fields and native behavior input. Edit keys, replace the behavior, create a pair from an existing entry, or copy/paste/duplicate/reorder/delete whole pairs. Copy/Paste also works in a known shared collection body, with caller locks, affected drafts and one workspace Undo/Redo protecting the edit. Copies retain the original key; set an independent key when the collection requires unique keys. The actual collection implementation defines runtime constraints and enumeration order. Helper/generated child inputs and entry-owned phases still require source ownership reconciliation.

Add **ReturnToSpawn**, **StayBack** or **Charge** from Movement and use **Edit movement bounds** for their native distance inputs. Return uses the original spawn point; StayBack retreats from a nearby player or matching enemy name. Charge acquires a diagonal player, then keeps its direction through the travel segment. Aligned X/Y targets are rejected by this game source. The editor preserves native timing, float range values and source history.

**FollowDistance** and **LockedFollowDistance** expose three movement handles: acquisition radius, stopping radius and cumulative travel limit. The travel line represents a distance budget, not a fixed destination. FollowDistance searches again each tick; LockedFollowDistance retains the living visible player acquired at entry and ends on target invalidation or its native timeout. Both clamp movement to the remaining travel budget and stop boundary, and complete after 500 ms of blocked movement. Locked stopping range stays strictly below acquisition range. Play uses the original controllers; the diagrams use actual sprites and prototype targets.

Add **DelayedOriginHazards** from Attacks for the native dormant projectile controller. Its XML chooser shows compatible projectiles owned by the enemy. Open **Hazard layout & arming** to choose Trail or Lattice, set the first lattice direction and inspect original startup/attempt timing and XML acceleration, arming and expiry. Trail emits backward fans from the moving host; Lattice uses fixed sites at ±5 tiles from the original spawn. The diagram shows the first layout with actual enemy art. Play renders received arming cues and executes the original controller; warning circles describe cues rather than collision bounds. Unstunned attempts can consume the volley limit even when no packet is emitted.

Play reuses the actual `State`, `Entity.Tick`, movement, targeting, transition, Spawn, Shoot, projectile-position and defense implementations, through the upstream headless BossPatternSim host. Enemy ticks are always 100 ms. Collision/player samples are 5 ms. The viewport advances the player on each WPF display frame rather than waiting for an enemy tick. Armor/ring loadouts, abilities, MP, regeneration, special class systems and the full player lifecycle remain pending.

The hitbox overlay uses the same geometry as collision: inclusive one-tile target squares, circular `Oryx4HitRadius` exceptions and projectile **points**, independent of sprite size. World position is at the character's feet. Sprites use the client's scale (an 8px character at size 100 occupies 0.8 tiles), while projectile points and collision boundaries project half a tile above the ground, matching the client's projectile height. Mouse aiming uses the same projection. Hidden, paused, stasis and invincible targets are skipped; piercing projectiles hit each target once. Parametric projectile X parity follows the client where its formula differs from server validation.

Client collision is sampled against authoritative enemy tick positions; enemy presentation interpolation does not change collision results or attack origins. The displayed enemy hitbox follows its rendered pose and can trail the runtime position within a tick. Full client collision interpolation, protocol latency, client hit reporting and special trajectory families are not fully reproduced. Unsupported motions are omitted and reported. No encounter receives a blanket verified-accurate label. See [compatibility](docs/COMPATIBILITY.md).

## Optional AI

The Assistant tab implements Continue with ChatGPT, separate account registrations, PKCE, state/nonce and signed ID-token validation, Windows DPAPI storage, serialized token renewal and session revocation. It drives a local `codex.exe app-server` over stdio using the documented ChatGPT-plan provider. Install a compatible Codex CLI and supply its executable path if it is not on PATH.

Enable selected-context sharing, enter a brief and send a message. Only the selected entity, supported constructor catalog, brief and requested traces are exposed through Studio's native tools. Proposals are validated with document revision/lock checks and require Preview/Apply; Apply is one undo. Bounded stationary simulations can test the current document or proposal. Built-in shell, browser, computer, connector and delegation capabilities are disabled in this integration; it uses its own isolated Codex home/workspace.

Live account sign-in and inference have **not** been verified in this delivery.
