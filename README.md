# Realm Behavior Studio

A working Windows desktop encounter editor for the supplied Raple Realms source. Version 0.1 is an incremental implementation, not the full product described in the roadmap.

**This server uses C# behavior definitions, not XML behaviors.** XML defines entities, projectiles, tiles and equipment. Studio imports C# `.Init(...)` definitions, preserves the complete source, edits the same document that Play consumes, and checks exports with the original compiler and native loader before writing them.

## Run

Install the .NET 10 SDK on Windows, then double-click **Start Studio.cmd**. The supplied workspace already has the SDK. This builds the app and opens its workspace. No Redis, game login, running server or AIR client is needed for Studio's current local test host.

The refreshed workspace uses a graphite theme, matching dark dropdowns, separate Encounter/Behavior/Source/Details views, and a full-width console. Drag the divider above Console to resize it; the two rightmost console buttons expand or collapse it. Panel sizes are saved with projects and remembered between launches. Parameter explanations are available on hover, with optional settings collapsed by default.

Select an action and **Add to state** to choose a real game constructor, fill its fields and inspect the source preview. Overloads, named arguments, arrays and optional defaults follow C# rules. Repeated arguments such as Taunt messages have separate editable fields. A phase's collapsed **Lifecycle** view shows its native callbacks and inherited parent actions; select a row to edit the original action. Imported original server files also expose helper arguments and compiler-resolved source constants. Factory and shared State roots appear in the library and graph. **Edit [definition]** opens a helper return, field, property getter or typed collection from the current source document. The banner identifies its known callers; **Return to encounter** restores the call view. Play uses the actual compiled helper and its original arguments.

Compiled previews load the edited complete server assembly in a separate process, retaining its embedded resources. The workspace stays available while preparing; Stop, switching entities or editing cancels the start. Native startup/tick failures stop that process. Source/build/resource/runtime fingerprints accompany traces and export verification. This expands executable source coverage; it does not certify all custom game-context, player or client mechanics. Source code executes with the current user's access: process separation is not a security sandbox.

Native child arrays appear as quieter rows such as **children · 2**. Select their contents to edit, reorder, duplicate, copy/paste or drag compatible actions into another typed list. The editor preserves the array's actual type and rejects incompatible children. Select a list or wrapper when adding a child. Prioritize starts with an editable native Wander child. Timed and OnDeathBehavior use the game's real callback rules; the lifecycle inspector shows the child's actual dispatch stage.

Helpers and source constructors with several native child parameters show a separate named slot for each scalar, array or expanded params list. Select the exact slot before using an action: occupied scalar slots offer **Replace child**, and optional empty slots can be filled again. Optional arrays remain visibly unassigned until a child creates their actual typed array. Cross-slot moves preserve the other arguments' C# binding, identities and undo. Shared collections with a declaration in this document offer **Edit [definition]**; unresolved or externally defined inputs retain **Open Source**.

Array and source-bound enumerable/read-only/concrete C# collection expressions such as `[new Wander(.2), ..sharedBehaviors]` expose the same typed child lists. Explicit children and spread inputs support reorder, duplicate, copy/paste, moves, deletion and undo; spread inputs move between collection lists while preserving their source expressions. Their values expand in compiled Play, preserving C# evaluation and sharing. Empty lists retain `[]`, and literal collections can use ordinary native playback. Source helpers and custom controllers can expose IEnumerable, IReadOnlyList, List and actual CollectionBuilder inputs. Filling an omitted or null input creates a target-typed collection; incompatible children or unconstructible targets reject atomically. The hierarchy shows source input order, and compiled Play runs the actual helper/controller dispatch. Ordinary collection initializers and target-typed new(...) initializers also support child-list editing while retaining their constructor arguments, braces and comments, including empty lists. Native object/member initializers and multi-argument Add inputs retain visible source regions and use compiled playback; Open Source selects the exact expression. Current-file helper/getter bodies open through their definition controls; other control flow remains in Source.

Helper calls and shared references in typed child slots support duplicate, reorder, move, copy/paste, delete and undo. Copies of shared references retain the same source value; helper copies retain their original arguments. Paste binds in the destination's complete source scope and rejects unavailable helpers or incompatible native types. Definition edits change the original declaration once for its callers; IDs, locks, undo and the focused view survive project reopen. Locked calls protect transitive shared contents. Removing the last call retains declared body identities and locks. Phase rename reconciles fully discovered literal references across known callers. Conditional returns expose separate source branches; other statements and unresolved child inputs keep an explicit reconciliation boundary. Discovery does not execute helpers/getters or substitute runtime arguments. Generated algorithms remain in Source; shared helpers also open their original definitions across project files. Wrong helper argument types and compiler errors preserve the last valid document. Source binding requires the original server file path saved in the project.

Entity thumbnails, enemies, the Wizard test character and projectiles use the supplied client's actual PNG sheets. Studio reads the client texture registrations and resolves the source XML's texture indices, including hex indices and animated character cells. Pixel art stays crisp while zooming. Sprites are loaded from the private client checkout, not bundled into the public application. Unsupported/missing texture registrations show a placeholder; alternate skins, procedural rendering and full client animation parity remain incomplete.

```powershell
./start-studio.ps1
# Another checkout:
./start-studio.ps1 -ServerRoot C:/path/to/raple-realms-7-server -ClientRoot C:/path/to/raple-realms-7-client
```

To build directly:

```powershell
dotnet build src/Studio.Desktop -c Release
dotnet run --project src/Studio.Desktop -- --server ../raple-realms-7-server
```

Build-time `-p:ServerRoot=...` controls references to private source. Run-time `--server ...` selects its resources and source catalog. They must refer to the same revision. Rebuild when changing private server source; restart Studio when changing resources. Private dependencies are intentionally outside this application directory.

The launcher builds into a directory identified by the application/server source version, allowing a refreshed build while an older window remains open. Save work in the older window before switching to the new one. Direct launch also accepts `--client <client folder>`; the sibling client is the default.

## First encounter

In **Behavior**, select a helper call or shared reference and choose **Edit …**. The editor opens the actual body even when it lives in another server file, showing its filename and known callers above the graph. Parameters and collection operations update that shared file; **Return to encounter** returns to the original caller. Undo/Redo, locks and saved definition focus persist with the source project. Editing a shared body affects its callers, so caller locks also protect those edits. **Rename** coordinates a fully discovered phase declaration, its callers' literal transitions and random-choice slots, and incoming native orders across source files. One Undo/Redo restores the complete edit. Required caller/order files join the project automatically; locks, unapplied affected drafts, duplicate names and unresolved generated/custom references reject the whole operation.

The **Source** tab has a project file picker. **Add file** includes an existing C# file from the original server compilation; edit a shared helper, then **Apply** checks the complete project. Switching files preserves unapplied drafts. Applied dependency edits have their own Undo/Redo, persist in save/recovery and recordings, and force native compiled playback even for a literal encounter. A multi-file **Export** produces a ZIP with every edited file at its original server-relative path and the native verification stamp. It never installs changes into the game checkout. Cross-file rename supports fully known native references; deletion/copy transactions and generated ownership remain pending. Encounter locks conservatively block shared-source edits. Unapplied drafts are local to the open window and are not part of a saved project.

1. Search for **Cave Pirate Brawler** in the entity library. Its real behavior contains Follow, Wander and Shoot.
2. Open Behavior and select Shoot in the tree. Change `count` or `coolDown`, then Apply changes. Expand More supported parameters to add spacing, fixed angle or per-volley rotation.
   Choose **Edit aim & spacing** to open the viewport editor. Drag aim, spacing or search radius; release commits one source edit, and Escape cancels a drag. Search radius uses native tile units. The preview shows the first volley's directions; Play runs actual prediction, rotation and effects. Compiler-known constants support visual editing; unknown expressions stay editable in Parameters or Source without executing getters.
   Expand **Projectile** to browse the selected enemy's real projectiles. Search names or effects, inspect the sprite and damage/lifetime/speed, then choose **Use projectile**. Choosing an index has one undo; source-driven owners retain their source boundary.
   Select **Follow**, **Orbit** or **StayCloseToSpawn** and choose **Edit movement bounds** to drag native ranges, radius or radius variance. Orbit also has a direction chooser, including the game's seeded choice. Home range snaps to whole tiles and its anchor is the state-entry position. These diagrams show parameter boundaries; Play runs the real movement.
   For **Spawn**, movement targets, entity-existence transitions and transformations, open the collapsed entity chooser to search real XML IDs and sprites. **Use entity** makes one undoable change; **Nearest player** uses native null targeting. The Add action form also offers **Choose from game entities**. Spawn accepts enemies; other pickers follow the native world-query/Resolve rules.
   Select **MoveTo**, **MoveTo2/3**, **SpawnRelativeMove**, **MoveLine** or **NewMove** and choose **Edit movement path** to drag the native destination or vector. **Preview this phase** draws 3 seconds of actual whole-phase movement with the current seed and stationary test player; forced phases bypass earlier setup. Green lines are sampled native movement, while dashed lines show requested parameters. NewMove needs **OrderedBehavior** dispatch and uses seconds for its cooldown.

   **InstantSpawnRing** creates native helpers with an XML entity chooser and the game's phase-exit/death cleanup. **Order**, **OrderOnce** and **OrderOnDeath** address nearby matching entities; enter a phase from the target entity. These orders do not filter by parent. During Play, **Details → Actors** shows actual sprites, IDs, phases, health and native parent links. Unassigned parents remain unassigned; the editor does not infer ownership from proximity. Trace exports include live actors and actor/parent IDs for native spawn, attack, transition, death and removal events. Known self/incoming orders follow phase renames; external targets retain their own phase names. Unresolved order ownership blocks ambiguous rewrites without running getters.

   **OwnedLaneEmitters** creates up to two native helper enemies. Its entity chooser accepts actual enemies with XML projectile 0; the collapsed **Lane emission** view shows that child's projectile art, damage, motion limits and a native Horizontal/Vertical/Cross chooser. The projectile index is fixed by the game. Helpers need a flat starting state: Play checks the loaded native definition and explains incompatible nested phases before entry. Edit `intervalMs` and `startupMs` using real millisecond values; the interval must be at least 100 ms. Play preserves helper packet ownership, remote launch positions, native motion and phase-exit/death/removal cleanup. Play draws received sanctuary, ring, cellar landing and ledger warnings on the ground. These markers follow native packets and expiry; they do not indicate safe positions. General owned-emitter source instrumentation and complete client particle rendering remain incomplete.
3. Choose a game weapon in the Player tab, set base attack/dexterity, and Apply & restart. Move with WASD/arrows in the viewport; aim with the mouse and hold left click to fire real projectiles. Weapon thumbnails and projectile textures come from the client. Scroll to zoom and middle-drag to pan.

   For **TimedRandomTransition**, open **Phase choices** to choose existing named destinations, add a slot, reorder or remove one. The game chooses one entry uniformly: two copies of a phase among three slots give it two of the three chances. The graph keeps one priority row and routes every known destination. Phase rename, clipboard and fragment mappings update all literal slots; source-produced target arrays remain editable in Source. Removing a referenced phase removes the entire incoming transition, preserving the existing branch-delete policy.
4. Use Play/Pause, step 100 ms, choose playback speed, inspect runtime timers under Details, or select a console event to inspect its behavior node. Right-click an unambiguous projectile to inspect its source action. The console supports filtering and clearing the visible log without deleting the saved trace; changing its breakpoint applies immediately.

   **Details → Actors** also shows live defense, recorded damage and damage credited to present players. **DamageTakenTransition** uses the credited total across phases; this game's `wipeProgress` flag does not reset it. **EntityHpLessTransition** matches a native XML-ID name substring and can select the host itself, so its picker explains that lookup. **HealSelf** adds an amount, with percentage based on current HP; null adds zero and an increment equal to current HP is skipped by the game code. **GiveTemporaryDefense** adds on entry and subtracts on exit. The editor preserves these source semantics.
5. Save a `.rbs` project. Open it to restore source, node IDs, brief, seed, arena size, player preset and locks. Recovery files are under `%LOCALAPPDATA%/RealmBehaviorStudio/Recovery`; Open project also opens `.rbs.recovery` files.
6. Export to a separate folder. Studio compiles the entire WorldServer source set with the edited file substituted, then loads its behavior database in the isolated native host. A `.cs.verification.json` sidecar records the checked inputs. Review the exported C# file before replacing its corresponding server source and rebuilding the server.

The project holds the **complete imported C# file**; changing a selected entity retains other definitions and loot in that file. Switching files retains edits in memory and writes recovery snapshots. Save projects per source file; a multi-document project container is not implemented yet.

In Behavior, select a named phase and use **Phase name → Rename** in Parameters to update its transition references. Expand **Organize** to duplicate a phase/branch/action, move it earlier or later, or delete it. Phase copies get unique names and their internal transitions follow the copied phases; external targets remain unchanged. Deleting a phase also removes incoming transitions to its deleted nested phases. One Undo restores the entire edit. Locks disable structural controls; dynamic/opaque references and unresolved child slots require source editing. Reordering phases changes initial entry, and reordering actions/transitions changes their priority within the runtime's separate execution lists.

Advanced source edits apply atomically after syntax/reference checks. Invalid edits stay in the source pane while the last valid visual document remains active. Full compiler and native loader validation happens during compiled Play and export. Factory-generated phases/actions remain opaque in the visual document; successful execution does not make their internals visually editable.

Use **Preview attacks** in Encounter to compare projectile density, health lost and no-damage observations. Density samples the reference player's native run; damage reruns the encounter independently at each plotted start. Select a dot for its actual health, duration and reference exposure. Test settings offer 25/81 points, spacing and 3/5/10-second runs; **Selected phase** bypasses earlier setup. **Export results** writes source/resource/build fingerprints and the recorded results. Green dots mean no damage observed for this player, seed and duration; shortened, unsupported and hit-override runs are excluded. These stationary prototype tests do not establish safety between points or across other paths/seeds. Source, selection or player-setting changes clear the result. **Player → Player start position** sets saved native coordinates before encounter entry.

Use **Fragments → Save selection** (or the command palette) to save selected child phases/actions as a local template. Check the values to expose and give each input a unique name. Select a destination phase or typed child list, choose a saved fragment, set its inputs and map external phase references, then **Preview insertion → Insert**. Preview uses the actual destination compiler/schema; Insert is one undo and gives the copied nodes independent identities. Self-directed native orders can follow the destination encounter, while orders to other entities retain their targets. Files use readable `.rbsfrag` JSON; **Export file** and **Import file** provide local sharing. The library lives under `%LOCALAPPDATA%/RealmBehaviorStudio/Fragments`. Helper/shared-value definitions remain in source and must exist in the destination. Generated/hidden phase references retain the existing source-reconciliation boundary.

Use **Timeline** after Play to inspect recorded phase, attack, movement, health and actor events. Select an event to follow its known source origin, then **Go to event**, click a marker, or choose a 5 ms position and **Seek**. Seeking reruns the actual encounter with recorded inputs, seed, player settings and ordered test overrides. **Play recording** follows that history; **Live from here** replaces future inputs with a new branch. **Save recording/Open recording** use readable `.rbsreplay` files containing encounter source, settings and traces. Changed source/resource/runtime dependencies and divergent native results reject replay. Forced-phase runs retain their bypass label. Movement markers use actual native tick/player samples; unknown controller origins remain unassigned. Replay rebuilds state instead of loading a fast snapshot; full player/client fidelity remains pending.

Use **Ctrl-click** or **Shift-click** in Behavior to select multiple nodes. **Ctrl+C / Ctrl+V** copies and pastes branches/actions with fresh identities and unique copied phase names. Drag a selection onto a phase to move it inside; use the top/bottom of a row to insert before/after it, or hold Ctrl to copy. **Ctrl+G** groups adjacent siblings into a real nested phase, which changes native entry/inheritance; Ungroup is available through Commands after incoming references are rerouted. **Delete** removes the selected branches and their incoming transitions in one undo. **Ctrl+K** searches editing commands, destination phases and source navigation. Double-click a phase card or use its tree arrow to collapse details; saved projects retain collapsed phases. Parameter edits apply to the focused item, while commands use the whole selection.

Phase cards show each transition's condition, destination and numbered priority. Click a condition to edit it; **Organize → ↑ / ↓** changes its position in the source and the runtime's evaluation order. The first matching transition wins, with active child phases checked before their parents. **Phase review** is collapsed by default and opens clickable missing-target errors, unreachable-phase notices, overlapping HP/player-distance conflicts and self-transition advisories. Selecting a transition draws its destination route. Reachability follows first-child entry and inherited transitions; opaque/custom nodes, dynamic destinations or duplicate names suppress definitive unreachable claims. These authoring notices do not certify encounter behavior or block simulation; missing-target errors still do.

Native `InitMany` ranges now appear in the entity library. Inline State lambdas expose a shared template: editing one variant updates the same source for every variant, with independent selection identities, locks, undo and save/reopen. The header shows how many variants share it. Play uses the actual compiled factory, canonical XML IDs and native registration precedence. Block factories and delegate getters retain their source boundary. Numeric XML gaps are reported as possible native initialization failures. `PetFollow` requires an actual pet/player owner and currently reports that playback prerequisite.

## What Play currently means

Add **SizeTransform** for native growth and shrinking, or **ChangeSize** for the game's size pulses. A **SizeTransformComplete** transition must reference the same transform instance running in the phase; use its shared definition to edit that object. Native bounds protect size-transform edits, including target-typed `new(...)` fields. Play restores the transform's entry size, glow and projectile settings on completion/exit; ChangeSize persists.

Select **SetAltTexture**, then open **Textures** to preview real XML/client variants and **Use as first texture**. The usual fields set the last ID, timer and looping. Zero selects the original texture; undefined IDs preserve the previous visible texture. **Details → Actors** shows actual size, texture stat, visible texture, glow and projectile-size base. The viewport renders size and texture; full client glow, projectile-scale graphics, texture masks and alternate particle effects remain pending. Appearance events and replay retain the native state changes.

Use **Encounter → Edit arena** to paint actual XML ground and static obstacles, erase objects, place the primary enemy/player, or add up to 64 extra native enemies. Search the sprite palette; choose square/circular bounds and 32–128 tiles. **Fill floor** changes the base ground. A brush stroke is one Undo/Redo while the editor is open. **Play** loads the scene through the game's map exporter/loader; all placed enemies execute native behaviors, and attacks, movement, cover, path/area tests and replay use that scene. Projects save tiles and spawn positions. Invalid blocked/out-of-bounds starts reject at initialization. Ground is dimmed for readability; sprite pixels and physics retain their game definitions. Ground damage/push/sink/zero-speed mechanics still need the complete player lifecycle and are explicitly unsupported. Arbitrary world execution, multiple actual players and full client collision remain pending.

Use **Map → Open map** to edit actual `.wmap` files, or **From arena** to start from the current encounter. The map keeps its full dimensions; scroll to zoom, middle-drag to pan, and **Focus tile** to see a selected cell at sprite scale. Paint ground/objects or elevation/region/terrain, and use **Inspect** for XML IDs and native configuration. Each stroke or inspector Apply is one Undo/Redo. **Save map** writes the game’s native format; original checkouts require saving a copy elsewhere. Unsaved map drafts recover under `%LOCALAPPDATA%/RealmBehaviorStudio/Recovery/Maps`. Native version 0/1 files save as equivalent version 2 cells. Limits are 2048 tiles per axis, one million cells and bounded dictionary/configuration/file sizes.

For playback, select a tile containing the current encounter enemy and choose **Use in arena**. The current prototype accepts 128×128 maps with supported static objects and up to 64 extra native enemies. Their `hp`, `name`, `size` and effect configuration runs through the actual native entity loader; sprite size follows the loaded value. Other dimensions and objects needing full world/player context stay editable/exportable and report their execution requirement. Ground hazard limitations also follow numeric native ground references. Native map saves retain object settings; save your behavior project or export its edited C# separately.

Play reuses the actual `State`, `Entity.Tick`, movement, targeting, transition, Spawn, Shoot, projectile-position and defense implementations, through the upstream headless BossPatternSim host. Enemy ticks are always 100 ms. Collision/player samples are 5 ms. The viewport advances the player on each WPF display frame rather than waiting for an enemy tick. Enemy sprites, shadows, health bars and displayed hitboxes blend between tick positions on each frame, following the client's linear position-update formula. Enemy walking direction and cadence follow that segment's velocity. Playback speed changes scheduling, never the step sizes. Native player walking frames follow movement speed/direction; attack frames follow the equipped weapon's cadence, including extended weapon art.

The player remains an offline test actor, now equipped with a real XML weapon. The catalog contains 237 weapons, with 197 currently supported. Firing uses XML damage/range/spread/rate, the original normal attack/dexterity formulas and seeded damage generator, weapon stat bonuses, original OnShoot volley tracking, projectile replacement/count/spread cycles and supported temporary self boosts/statuses. Hits call the original `Player.EnemyHit`; kills run native death callbacks, while Boss Lab suppresses loot/progression. Unsupported special hit activations and cursor grenades are disabled with reasons. Armor/ring loadouts, abilities, MP, regeneration, special class systems and the full player lifecycle remain pending.

The hitbox overlay uses the same geometry as collision: inclusive one-tile target squares, circular `Oryx4HitRadius` exceptions and projectile **points**, independent of sprite size. World position is at the character's feet. Sprites use the client's scale (an 8px character at size 100 occupies 0.8 tiles), while projectile points and collision boundaries project half a tile above the ground, matching the client's projectile height. Mouse aiming uses the same projection. Hidden, paused, stasis and invincible targets are skipped; piercing projectiles hit each target once. Parametric projectile X parity follows the client where its formula differs from server validation.

Client collision is sampled against authoritative enemy tick positions; enemy presentation interpolation does not change collision results or attack origins. The displayed enemy hitbox follows its rendered pose and can trail the runtime position within a tick. Full client collision interpolation, protocol latency, client hit reporting and special trajectory families are not fully reproduced. Unsupported motions are omitted and reported. No encounter receives a blanket verified-accurate label. See [compatibility](docs/COMPATIBILITY.md).

## Optional AI

The Assistant tab implements Continue with ChatGPT, separate account registrations, PKCE, state/nonce and signed ID-token validation, Windows DPAPI storage, serialized token renewal and session revocation. It drives a local `codex.exe app-server` over stdio using the documented ChatGPT-plan provider. Install a compatible Codex CLI and supply its executable path if it is not on PATH.

Enable selected-context sharing, enter a brief and send a message. Only the selected entity, supported constructor catalog, brief and requested traces are exposed through Studio's native tools. Proposals are validated with document revision/lock checks and require Preview/Apply; Apply is one undo. Bounded stationary simulations can test the current document or proposal. Built-in shell, browser, computer, connector and delegation capabilities are disabled in this integration; it uses its own isolated Codex home/workspace.

Live account sign-in and inference have **not** been verified in this delivery. Offline tests cover signatures, tampering, permissions, rotation locking, protected storage and streamed/canceled/failed protocol turns using a fake peer. Actual model entitlement and account usage are established by a real completed inference turn, not a model list. Sign-in adds no free allowance. Eligible plan usage and credits are governed by OpenAI's current policies.

Official references: [OSS registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [accounts and renewal](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [Codex provider configuration](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server), [preview restrictions](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

## Architecture and next work

- `Studio.Core`: lossless syntax document, stable node metadata, revisions, atomic patches, undo/redo, project persistence.
- `Studio.Raple`: source catalog, typed constructor catalog, validation, restricted binding, native compilation/process client, traces and verification provenance.

- `Studio.Desktop`: WPF workspace, custom viewport/graph, inspector, player controls, source editor, proposals and account UI.
- `Studio.AI`: official public-client OAuth lifecycle and Codex app-server transport. It has no dependency on the game.
- `tests`: editor/runtime/differential checks, authentication contracts and desktop smoke automation.
